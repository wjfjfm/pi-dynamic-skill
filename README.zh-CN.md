# pi-dynamic-skill

[English](README.md) | [简体中文](README.zh-CN.md)

为 [Pi](https://github.com/earendil-works/pi) 提供 skill 的动态装载与替换，**不增加任何 Tool**。

`dynamic-skill` 根保留在 Pi 原生 skill 目录中，description 引导 Agent 在新增记忆或维护 skill 树时按需读取。Root Skills 区域以原生元数据格式展示各根的直接子 skill，不自动展开任何 skill 正文。每个节点包含自动生成的直接子 skill 目录，Agent 使用普通 `read` 即可逐层导航，使用 Pi 已有的 `write`、`edit` 创建和更新 skill。

## 安装

```sh
pi install git:github.com/wjfjfm/pi-dynamic-skill
```

安装后 reload 或重启 Pi。扩展复用 Pi 原生发现的有效 `dynamic-skill`，支持用户、项目、自定义路径和包来源。同名优先级沿用 Pi 的规则，不合并重复根节点。

未发现根 skill 时，扩展创建 `~/.pi/agent/skills/dynamic-skill/SKILL.md`（设置 `PI_CODING_AGENT_DIR` 时使用对应目录）。默认复制 `templates/dynamic-skill/SKILL.md`，包含使用说明、树维护规则、LRU 策略及编写示例，允许用户修改。已有根文件保留，不覆盖或自动迁移。默认文件位于扩展安装目录之外，包更新不会删除后来编写的 skill。

## 配置

可选配置位于 `~/.pi/agent/dynamic-skill.json`（或 `PI_CODING_AGENT_DIR` 下）：

```json
{ "capacity": 20 }
```

容量须为正安全整数。启动及 `/reload` 时读取，compact 使用已加载值。缺失时使用 20；错误时警告并回退到 20。缩小容量将溢出项移入待逐出区，根不占容量。不自动创建配置文件。

## 树结构

```text
dynamic-skill/
├── SKILL.md
└── skills/
    ├── development/
    │   ├── SKILL.md
    │   └── skills/
    │       └── testing/
    │           └── SKILL.md
    └── research/
        └── SKILL.md
```

每个节点必须有 `SKILL.md`。子节点始终放在父节点的 `skills/<name>/SKILL.md`。不必提前创建空 `skills/`：Pi 的 `write` 会自动创建父目录。没有子节点时无需生成目录块。

```markdown
---
name: testing
description: 编写或排查测试时使用。
---
检查项目的测试命令，覆盖相关行为。
```

子 skill 的 name 必须与目录名一致，最多 64 个小写字母、数字或单连字符；description 非空白且不超过 1024 字符。自定义正文可以为空。缺失或非法节点会报告诊断，并暂不加入导航，修复后自动纳入。子节点不支持符号链接。

管理范围内的每个 `SKILL.md` 都代表一个 skill，包括隐藏目录或错误位置中的文件。启动/reload 会检查所有这些文件，即使其父 skill 缺失或不合法。成功的 write/edit 会检查被修改 skill 的路径、元数据及祖先 skill。文件必须包含闭合的 YAML frontmatter；根目录名及其 `name` 均须为 `dynamic-skill`。这些要求不作用于管理范围之外的文件。

## 自动导航

有合法子节点的父 skill 会生成以下区块：

```markdown
<!-- dynamic-skill -->
## Child skills
Auto-generated by dynamic-skill, do not write or edit.

- [testing](./skills/testing/SKILL.md): 编写或排查测试时使用。
<!-- /dynamic-skill -->
```

每层只列出直接子节点。扩展保留区块外的正文，移除过期链接，内容未变时不重写文件。读取子 skill 后即可看到其正文和下一层入口。链接相对于当前 `SKILL.md` 所在目录解析。

更新导航时，先读取文件，计算生成区块的替换补丁，确认原内容未变后，通过临时文件和原子 rename 落盘。检测到冲突就重新读取并扫描子 skill，最多尝试三次；持续冲突时保留并发修改并报告诊断。这是无锁冲突检测，不是原子比较并交换：最终检查与 rename 之间仍存在竞争窗口。

## 运行行为

使用 `/dynamic-skill` 查看已识别的根目录，以及当前会话的活跃数量／容量、待逐出数量。数量以上一次 compact/reload 结算为准；查看状态不会改变队列。

- Root Skills 展示已识别根的直接子 skill，而不是根本身。第一层入口固定展示，不占 LRU；更深层 skill 使用活跃／待逐出队列。所有正文按需 read。列表在启动及成功 compact/reload 后刷新，两次刷新之间保持稳定。
- 启动、`/reload` 及 compact 成功后全量扫描管理范围。compact 后先刷新父索引，再结算访问并刷新上下文列表，不重载其他 Pi 资源或扩展。通过 Pi 的 warning UI 汇总显示 `[dynamic-skill] Skill warnings`（无 UI 时输出至 stderr），不阻止会话运行。子 skill 导航静默修正；标记边界损坏、可能误删正文时仍报告诊断。初始化的意外异常也只作为警告提示。
- 向模型上下文投影 `Dynamic skills` 章节：独立的 Root Skills、活跃与待逐出列表。使用及树维护说明来自根 SKILL.md，不再由代码单独注入。根文件及固定展示的第一层子 skill 不占 LRU；旧状态中的这些条目将在下次结算时移出。各组均使用 Pi 原生 `formatSkillsForPrompt` 输出（`name`、`description`、`location`），沿用转义及 `disable-model-invocation` 行为。不自动展开正文，投影消息不写入会话历史。
- 树内 `SKILL.md` 的 write/edit 成功后，读取真实文件进行校验，只刷新该节点与直接父节点的目录，不重写其他分支。
- 元数据或路径不合法时，在原 tool result 后追加 `[dynamic-skill]` 诊断。文件仍保留，工具成功状态、原内容块和 details 不变；父节点可刷新时，会移除失效子节点的入口。
- 不拦截或阻止写入。自动区块被手动修改后会重新生成；标记对损坏时报告问题，不猜测范围覆盖作者正文。
- 失败操作、read、辅助文件和树外文件不触发维护。启动/reload 及 compact 成功后全树同步；bash 或外部编辑器的变化除此之外只会在相关节点刷新时被发现。
- 使用 `resources_discover` 处理初始化/reload、`tool_result` 维护 write/edit 后的目录、`session_compact` 进行压缩成功后的访问结算、`context` 投影 skill 列表。没有后台监听、定时器、逐请求扫描或跨进程锁；当前版本不协调多个 Pi 同时写入同一父节点。

成功 compact 后及 `/reload` 时，从当前会话分支结算合法 skill 的 READ／WRITE／EDIT。按规范化路径去重，并按最后一次成功访问从早到晚处理；每个 skill 在本轮结算中只更新一次 LRU。带版本的自定义 session entry 保存活跃区、待逐出区及结算边界，不进入模型上下文。失败操作和其他分支不计入，不增加 READ hook。

`src/lru.ts` 已实现二分递进 LRU 排序算法：新 skill 插入下标 `floor(N / 2)`，已有 skill 从下标 `i` 晋升到 `floor(i / 2)`。下标从 0 开始，队首最受保护，被越过的节点依次后移一位。skill 以规范化的绝对文件路径区分。`accessSkillState` 分别维护活跃区与待逐出区，并接受显式的活跃容量。待逐出 skill 再次访问时，以 `floor(active.length / 2)` 重新进入活跃区；溢出的活跃队尾移入待逐出区。已有 20 个活跃 skill 时，访问活跃队尾晋升至下标 9，访问待逐出或新 skill 则插入下标 10。默认活跃容量为 20，已接入访问结算及会话持久化。列表在两次结算之间保持稳定，compact/reload 后刷新。待逐出列表提示 Agent 再次读取以保留。在下一次成功 compact/reload 时，已经预告且未被成功 READ／WRITE／EDIT 的候选从列表移除；本轮新溢出的项获得新的预告周期。自定义 session entry 记录哪些候选已进入模型上下文，避免连续 reload 在预告展示前移除候选。逐出不删除文件。结算时已删除或不合法的 skill 不予保留。

已读取的子 skill 正文仍是历史中的普通工具结果；刷新根节点或修改文件不会改写过去的 tool result。本扩展不压缩会话历史。

## 包接口

其他应用也可以直接导入已有的文件接口，无需加载扩展：

```ts
import { createSkill, reloadSkills } from "pi-dynamic-skill";

const skill = await createSkill(parentSkillsDirectory, {
  name: "testing",
  description: "编写或排查测试时使用。",
  content: "检查项目的测试命令。",
});
const { skills, diagnostics } = reloadSkills(parentSkillsDirectory);
```

`createSkill` 遇到重名时抛出 `SkillExistsError`。`reloadSkills` 使用 Pi 原生目录扫描器返回元数据，不激活扩展或注入上下文。知识生成和存储位置由调用方决定。作为 Git 依赖安装时，`prepare` 自动构建 JavaScript 与类型声明。

## 开发

```sh
npm ci
npm run typecheck
npm test
pi -e ./src/index.ts
```

开发基于 Pi SDK 0.85.1。测试覆盖 Pi 原生 read/write/edit 和真实会话运行时，无需模型凭据。
